# 0003. CSS class names with BEM

- **Date:** 2026-11-10
- **Status:** accepted

## Context

With a single hyphen for everything, names like `button-text`, `button-primary` and `button-body` look the same, even though the first is another component, the second a variant and the third a part of the button.

## Decision

Classes follow the **BEM** convention (Block, Element, Modifier), which matches how components are organized in Figma:

| BEM             | In Figma           | Example           |
| --------------- | ------------------ | ----------------- |
| Block           | The component      | `button`          |
| Element (`__`)  | An inner layer     | `button__body`    |
| Modifier (`--`) | A variant property | `button--primary` |

States use the browser's own (`:active`, `:disabled`, `[aria-busy="true"]`), without classes.

## Alternatives considered

- **A hyphen for everything:** it does not tell components, parts and variants apart.
- **Parts with a hyphen and variants with `data-` attributes (`data-variant="primary"`):** also valid and very close to Figma; BEM was preferred because it is the best-known standard.

## Consequences

- Reading a class tells whether it is a component, a part or a variant.
- Searching for `button--` finds every variant, and `button__` every part.
- Names are longer, in exchange for being unambiguous.

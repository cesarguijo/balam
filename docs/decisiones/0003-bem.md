# 0003. Nombres de clases CSS con BEM

- **Fecha:** 2026-11-10
- **Estado:** aceptada

## Contexto

Con un solo guion para todo, nombres como `boton-texto`, `boton-relleno` y `boton-cuerpo` se ven iguales, aunque el primero es otro componente, el segundo una variante y el tercero una parte del botón.

## Decisión

Las clases siguen la convención **BEM** (Bloque, Elemento, Modificador), que corresponde a cómo se organizan los componentes en Figma:

| BEM | En Figma | Ejemplo |
| --- | --- | --- |
| Bloque | El componente | `boton` |
| Elemento (`__`) | Una capa de adentro | `boton__cuerpo` |
| Modificador (`--`) | Una propiedad de variante | `boton--relleno` |

Los estados usan los del navegador (`:active`, `:disabled`, `[aria-busy="true"]`), sin clases.

## Alternativas consideradas

- **Un guion para todo:** no distingue componentes, partes y variantes.
- **Partes con guion y variantes con atributos `data-` (`data-tipo="relleno"`):** también válida y muy cercana a Figma; se prefirió BEM por ser el estándar más conocido.

## Consecuencias

- Al leer una clase se sabe si es un componente, una parte o una variante.
- Buscar `boton--` encuentra todas las variantes y `boton__` todas las partes.
- Los nombres son más largos, a cambio de ser inequívocos.
